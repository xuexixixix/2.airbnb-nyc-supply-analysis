## 一、北极星指标

```
北极星：平台 GMV（总成交额）

GMV ≈ SUM(estimated_revenue_l365d)
```

### 为什么不是「出租率」？

出租率是**效率**指标，无法单独反映平台规模：

| | 房源数 | 出租率 | 哪个平台更赚钱？ |
|---|-------|-------|----------------|
| 平台 A | 100 | 90% | |
| 平台 B | 50,000 | 45% | **B** |

只看出租率会得出误导性结论。**出租率是辅助指标，不是北极星。**

> **本项目实际分析主线**：GMV 是平台业务北极星，但本项目不直接优化 GMV，而是解释 GMV 的供给端结构。
> 因此分析主线用「有效短租供给」：短租型 + 可订 + 近 12 个月有评论 = **4,050 套（13.4%）**。
> 出租率只做辅助诊断，不单独汇报绝对值。

## 二、指标树

```
北极星：平台 GMV ≈ SUM(estimated_revenue_l365d)
│
├── 因子拆解（回答「为什么」——可归因、可干预）
│
│   GMV = 有效房源数 × 出租率 × 平均成交房价 × 365
│         └─ 规模       └─ 效率   └─ 价格
│
│   ① 有效房源数
│        = COUNT(availability_365 > 0)
│        = 挂牌数 × 可订率
│        其中 可订率 = 1 − 僵尸率
│              僵尸率   = COUNT(availability_365 = 0) ÷ COUNT(*)
│
│   ② 出租率
│        = 已订间夜数 ÷ 可订间夜数
│        = AVG(estimated_occupancy_l365d ÷ 365)
│
│   ③ 平均成交房价（成交量加权均价）
│        = SUM(estimated_revenue_l365d) ÷ SUM(estimated_occupancy_l365d)
│
└── 维度拆解（回答「在哪里」——定位问题区域）
     ├─ 地理维度：neighbourhood_group_cleansed（5 个行政区）
     ├─ 房型维度：room_type（4 类）
     └─ 房东维度：calculated_host_listings_count（个体 vs 职业房东）
```

### 为什么用成交量加权均价，而不是 `AVG(price)`？

| 口径 | 字段 | 问题 |
|------|------|------|
| 挂牌价简单平均 | `AVG(price)` | ❌ `price` 是**房东想卖多少**，非实际成交；且为字符串 `"$150.00"`，须先清洗 |
| 平台报价值 | `AVG(price_quote_price_per_night)` | ⚠️ 是**平台报价**，仍非成交 |
| **成交量加权均价** | `SUM(estimated_revenue_l365d) ÷ SUM(estimated_occupancy_l365d)` | ✅ **按真实成交间夜加权**，最接近实际 |

## 三、指标定义表

| 指标名 | 层级 | 计算口径 | 数据来源 | 业务含义 | 当前实测值 |
|--------|------|---------|---------|---------|-----------|
| 平台 GMV | 北极星 | `SUM(estimated_revenue_l365d)` | listings | 平台年成交总额 | 待计算 |
| 挂牌房源数 | 一级 | `COUNT(id)` | listings | 账面规模 | 30,259 |
| 僵尸房源数 | 二级 | `COUNT(availability_365 = 0)` | listings | 挂着不接客 | 6,791 |
| 僵尸率 | 二级 | 僵尸数 ÷ 挂牌数 | listings | 供给虚高程度 | **22.4%** |
| 可订率 | 二级 | 1 − 僵尸率 | listings | 可订房源占比（不是有效短租供给率） | 77.6% |
| 有效房源数（可订房源） | 一级 | `COUNT(availability_365 > 0)` | listings | 可订规模（含长租） | 23,468 |
| **有效短租供给数** | **分析主线** | 短租 + 可订 + 有评论 | listings | **短租型中的有效供给** | **4,050** |
| **有效短租供给率** | **分析主线** | 有效短租供给数 ÷ 挂牌数 | listings | **供给真实性** | **13.4%** |
| 出租率 | 辅助 | `AVG(estimated_occupancy_l365d ÷ 365)` | listings | 效率诊断（仅同类型相对比较） | 短租整租 49.7% / 长租整租 10.0% |
| 平均成交房价 | 辅助 | `SUM(revenue) ÷ SUM(occupancy)` | listings | 价格水平 | 待计算（依赖出租率） |
| 短租持证率 | 二级 | `COUNT(license 非空且≠Exempt) ÷ COUNT(*)` | listings | 合规程度 | **7.70%** |

> **可信度分级**：挂牌数、短租占比、零评论率 = 高；有收入短租 = 中（175 条收入缺失）；
> 出租率、GMV = 低（依赖评论反推与 70% 上限）。分析主线只使用高可信度指标；
> 出租率只做同类型内部相对比较，不报绝对值。

### 分析主线：有效短租供给漏斗

本项目实际回答的是「有效供给有多少」，所以把 5,540 套短租型挂牌再拆一层：

| 口径 | 数量 | 占全部挂牌 | 定义 |
|---|---:|---:|---|
| 短租型挂牌 | 5,540 | 18.3% | `minimum_nights < 30` |
| 可订短租 | 5,118 | 16.9% | 短租 + `availability_365 > 0` |
| 有需求短租 | 4,184 | 13.8% | 短租 + `number_of_reviews_ltm > 0` |
| **有效短租供给** | **4,050** | **13.4%** | 短租 + 可订 + 有需求 |
| 有收入短租 | 4,009 | 13.2% | 短租 + `estimated_revenue_l365d > 0` |

拆解（5,540 = 5,118 + 422；5,118 = 4,050 + 1,068）：

```
5,540 短租型
├─ 5,118 当前可订
│  ├─ 4,050 可订 + 有评论
│  │  ├─ 4,009 有收入
│  │  └─ 41 无收入记录
│  └─ 1,068 可订 + 零评论
└─ 422 当前不可订
   ├─ 134 有评论（曾经营业，现在关闭）
   └─ 288 零评论
```

**这不是对 5,540 的修正，而是对它的再拆解。** 「72.4% 有成交」仍然成立（4,009 / 5,540）；
新增的是「可订且有需求」的严格口径 4,050（13.4%）。

## 四、维度拆解的「比较目标」

> ⚠️ 切分维度是**手段**，比较指标才是**目的**。
> 只写「按行政区切」不算完成 —— 必须写清**切开之后比什么**。

| 拆分维度 | 字段 | 比较什么 | 想回答的业务问题 |
|---------|------|---------|----------------|
| 行政区 | `neighbourhood_group_cleansed` | 僵尸率 / 出租率 / 成交均价 | 哪个区的供给最不健康？ |
| 房型 | `room_type` | 出租率 / 成交均价 | 整租 vs 独立间的经营模式差异？ |
| 房东规模 | `calculated_host_listings_count` | 僵尸率 / 持证率 | 职业房东 vs 个体房东，谁在合规经营？ |
| 街区 | `neighbourhood_cleansed` | 房源密度 / 均价 | 供给是否在地理上过度集中？ |

## 五、设计约束（本项目自定规则）

所有指标必须满足：

1. **可计算** —— 字段在 2026-06-14 快照中真实存在且非全空（已核验）
2. **有业务含义** —— 能回答一个具体的运营问题，而非纯统计量
3. **可归因** —— 优先选择可被运营动作影响的指标
4. **不含幻觉指标** —— 禁止出现数据中不存在的量（搜索量、转化率、竞品数据）

### ❌ 已因数据缺失而放弃的指标

| 原计划指标 | 依赖字段 | 状态 |
|-----------|---------|------|
| 房东运营年限 | `host_since` | ✅ 改用 `hosts_time_as_host_years` |

| **房东响应度** | `host_response_rate` / `host_acceptance_rate` | ❌ **取消** |
| **即时预订率** | `instant_bookable` | ❌ **取消** |
