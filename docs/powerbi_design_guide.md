# Power BI 看板设计稿

> 目标：1 页看板，5 个视觉对象，讲清楚核心结论。
> **不是把所有图都塞进去** —— 面试官只给你 2 分钟，一页能讲完的比三页讲不完的强。
>
> 数据源：直连 MySQL `airbnb_nyc`（不导出 CSV —— 直连数据库更专业）

---

## 一、前置准备

### 1. 确认 MySQL 连接器

Power BI 连 MySQL 需要 **MySQL Connector/NET**。

```
下载：dev.mysql.com/downloads/connector/net/
选 .NET 版本（不是 ODBC）→ 安装 → 重启 Power BI
```

⚠️ 如果连不上（报错 "无法加载 MySQL 提供程序"），就是这个没装。

### 2. 打开 Power BI Desktop

开始菜单搜「Power BI Desktop」。

## 二、连接数据源

```
主页 → 获取数据 → 更多 → 数据库 → MySQL 数据库 → 连接
```

填写：

| 字段 | 值 |
|------|-----|
| 服务器 | `localhost` |
| 数据库 | `airbnb_nyc` |

**凭证**：数据库页 → 用户名 `root`、密码（你的 MySQL 密码）

**导航器里只勾 `listings` 这一张表**，其余不勾。

> **为什么只要一张表**：看板的全部指标都能从 `listings` 单表算出来
> （已验证：僵尸房源 8,559 套，与 Join reviews 表算出的结果完全一致）。
> 导入 `calendar`（1115 万行）会让文件巨大且变慢，没必要。

点击 **转换数据**（不是"加载"）—— 我们要先加几个计算列。

## 三、加计算列（在 Power Query 或 DAX 里都行）

> **推荐用 DAX 计算列**（建模 → 新建列），因为语法更直观、便于后续修改。

### 列 1：生命周期

```
生命周期 =
SWITCH(
    TRUE(),
    listings[number_of_reviews] = 0, "1. 僵尸（从未有评论）",
    listings[number_of_reviews_ltm] = 0, "3. 沉寂（曾有评论，近一年无）",
    "2. 活跃（近一年有评论）"
)
```

### 列 2：房源类型

```
房源类型 =
IF(listings[minimum_nights] >= 30, "长租型（≥30天）", "短租型（<30天）")
```

### 列 3：房东规模档

```
房东规模档 =
SWITCH(
    TRUE(),
    listings[calculated_host_listings_count] = 1, "1套",
    listings[calculated_host_listings_count] <= 5, "2-5套",
    listings[calculated_host_listings_count] <= 19, "6-19套",
    "20套以上"
)
```

### 列 4：持证状态

```
持证状态 =
SWITCH(
    TRUE(),
    ISBLANK(listings[license]), "无记录",
    listings[license] = "Exempt", "已豁免",
    "有执照"
)
```

## 四、建度量值（建模 → 新建度量值）

> 逐个复制粘贴即可。度量值和计算列不同：**度量值随筛选条件动态变化**，
> 计算列是每行固定值。指标一律用度量值。

```
总房源数 = COUNTROWS(listings)

有效房源数 = CALCULATE(COUNTROWS(listings), listings[availability_365] > 0)

有效供给率 = DIVIDE([有效房源数], [总房源数])

僵尸房源数 = CALCULATE(COUNTROWS(listings), listings[number_of_reviews] = 0)

沉寂房源数 =
CALCULATE(
    COUNTROWS(listings),
    listings[number_of_reviews] > 0,
    listings[number_of_reviews_ltm] = 0
)

活跃房源数 = CALCULATE(COUNTROWS(listings), listings[number_of_reviews_ltm] > 0)

零评论率 =
DIVIDE(
    CALCULATE(COUNTROWS(listings), listings[number_of_reviews_ltm] = 0),
    COUNTROWS(listings)
)

持证房源数 =
CALCULATE(
    COUNTROWS(listings),
    NOT ISBLANK(listings[license]),
    listings[license] <> "Exempt"
)

持证率 = DIVIDE([持证房源数], [总房源数])

长租房源数 = CALCULATE(COUNTROWS(listings), listings[minimum_nights] >= 30)

长租占比 = DIVIDE([长租房源数], [总房源数])

关店率 =
DIVIDE(
    CALCULATE(COUNTROWS(listings), listings[availability_365] = 0),
    COUNTROWS(listings)
)

平均挂牌价 = AVERAGE(listings[price])
```

**每个度量值的格式**：选中它 → 格式 → 设为百分比（零评论率、持证率等）或整数。

### ② 生命周期三档（环形图）

```
可视化：环形图
图例：listings[生命周期]
值：  [总房源数]
```

**配色**（见第七节）：
- 活跃 → `#2a78d6`（蓝）
- 沉寂 → `#eb6834`（橙）
- 僵尸 → `#1baf7a`（青）

**标题**：`平台最大的一档是「曾经有、后来没了」`

⚠️ 环形图最多 3 个扇区才好看 —— 正好我们是 3 档。

---

### ③ 四维度极差对比（条形图）

```
可视化：堆积条形图 / 簇状条形图
轴：  维度名称（需要一张手工输入的小表，见下）
值：  极差百分点（手工输入或度量值）
```

**⚠️ 这个图需要手工准备数据** —— 因为「极差」是跨分组的聚合结果，
没法直接用一张明细表画出来。

**做法**：主页 → 输入数据 → 建一张 4 行的小表：

| 维度 | 极差 | 说明 |
|------|------|------|
| 房型 | 70.0 | 整租 9.4% 至 酒店房 77.2% |
| 房东规模 | 47.9 | 1套 6.6% 至 20套+ 54.5% |
| 持证状态 | 33.6 | 有执照 5.2% 至 已豁免 38.9% |
| 地理 | 27.0 | 布鲁克林 9.4% 至 曼哈顿 36.4% |

> **数据来源**：`sql/12_dimension_comparison.sql`
> **口径**：仅统计短租型房源（`minimum_nights < 30`，n=5,540）

**标题**：`在真正的短租里，四个维度都有显著差异（仅短租型）`

---

### ④ 房东规模趋势（可选，若空间够）

```
可视化：柱状图
X 轴：listings[房东规模档]
Y 轴：零评论率（需要新建度量值，见下）
筛选：listings[房源类型] = "短租型（<30天）"   ← 关键！
```

**必要性**：不筛选的话会得到 U 型（错误结论）。
筛选后是**单调递增**。

**新增度量值**：

```
零评论率_短租 = 
CALCULATE([零评论率], listings[minimum_nights] < 30)
```

**标题**：`房东规模越大，零评论率越高（仅短租型）`

---

### ⑤ 街区地图（气泡地图）

```
可视化：地图（内置）
纬度：listings[latitude]
经度：listings[longitude]
图例：listings[neighbourhood_cleansed]  ← 或不用图例
大小：总房源数
颜色（工具提示）：零评论率
```

**做法**：把 `零评论率` 拖到「工具提示」，悬停时显示。

**标题**：`零需求房源的地理分布`

> Power BI 内置地图是**气泡地图**，不是分区着色图。
> 分区着色（choropleth）需要 Shape Map + TopoJSON，配置较麻烦。
> **气泡地图够用了** —— 而且能同时展示"房源密度"和"零评论率"两个信息。

## 九、导出与提交

### 1. 保存 .pbix 文件

```
文件 → 另存为 → 放到项目根目录的 reports/ 文件夹
命名：airbnb_nyc_dashboard.pbix
```

### 2. 导出截图

```
文件 → 导出 → 导出为图像 → PNG
存到 visualizations/powerbi_dashboard.png
```

**为什么两个都要**：
- `.pbix` 证明你真做了
- **截图**放进 README —— 面试官不会下载 .pbix 打开看，但一定会看 README 里的截图

### 3. ⚠️ 提交前注意

`.pbix` 文件里可能嵌了**数据库密码**。

**提交前先在 Power BI 里改数据源凭证类型**，或者**不提交 .pbix**（只提交截图）。

> 不确定的话：**只提交截图，不提交 .pbix**。安全第一。

## 十、常见问题

| 现象 | 原因 | 解决 |
|------|------|------|
| 连不上 MySQL | 缺 Connector/NET | 去 dev.mysql.com 下载安装 |
| 中文字段名显示乱码 | 编码问题 | 连接字符串加 `charset=utf8mb4`（高级选项里） |
| 房东规模图呈 U 型 | 没筛选短租型 | 加筛选器 `minimum_nights < 30` |
| 数字是小数不是百分比 | 格式没设 | 选中度量值 → 格式 → 百分比 |
| 图表配色改不动 | 改错了地方 | 格式 → 数据颜色，不是在"主题"里改 |
