# SQL 查询目录

本项目所有分析查询存放在此。每个文件 = 一个业务问题。

## 怎么跑

```bash
# 列出所有查询
python scripts/run_sql.py

# 跑某一个
python scripts/run_sql.py sql/01_zero_review_by_area.sql
```

## 文件命名规范

```
NN_做什么.sql
```

- `NN` —— 两位序号，按分析顺序排列
- 用英文小写 + 下划线

## 每个 SQL 文件该写什么

**不要只写 SQL。** 好的分析查询文件应该包含：

```sql
-- 业务问题
--     这个查询想回答什么？
--
-- 为什么这么写
--     口径选择、为什么要用比例而不是绝对数，等等
--
-- 结论
--     跑出来的结果说明了什么？（跑完后补上）

SELECT ...;
```

**为什么**：三个月后你自己会忘记当时在想什么。别人看你的代码时，
**注释里写的业务思考，比 SQL 语法本身更能体现你的水平。**

## ⚠️ 结论修正记录

本项目的核心结论经历过**两轮重大修正**，**保留痕迹不覆盖**：

### 第一轮：成分效应

| 原始结论 | 修正后 | 原因 | 修正文件 |
|---------|-------|------|---------|
| 持证效应 67.3 pp | **24.4 pp** | 长租/短租是混淆因素 | `07_license_stratified.sql` |
| 「44% 开门但没客」 | 需按长短租分开理解 | 混入了 81.7% 的长租型房源 | `06_minimum_nights_structure.sql` |

### 第二轮：稀释效应（推翻 4 条）

| 原始结论 | 修正后 | 原因 | 修正文件 |
|---------|-------|------|---------|
| 地理均匀（5.3 pp） | **27.0 pp** | 长租型稀释了真实差异 | `12_dimension_comparison.sql` |
| 房型均匀（1.3 pp） | **70.0 pp**（差异最大的维度） | 同上 | `12_dimension_comparison.sql` |
| 房东规模呈 U 型 | **单调递增** | 同上 | `12_dimension_comparison.sql` |
| 持证 24.4 pp | **33.6 pp**（max-min 口径） | 口径统一 | `12_dimension_comparison.sql` |

> **修正的深层原因（一句话）**：
> 平台上 81.7% 的房源是长租型，且它的零评论率在各维度上高度一致（~74.5%），
> **像一层均匀的底噪，把短租型内部的真实信号盖住了**。
>
> **教训**：分组比较之前，先确认两组是不是同一种东西。

## 常用语法备查

```sql
-- 查看表结构
SHOW COLUMNS FROM listings;

-- 看某列的取值分布
SELECT room_type, COUNT(*) FROM listings GROUP BY room_type;

-- 条件计数（数满足条件的行）
SUM(CASE WHEN 条件 THEN 1 ELSE 0 END)

-- 百分比（注意 100.0，避免整数除法）
ROUND(100.0 * 分子 / 分母, 1)
```
